# Hololive Dreams Jump Rope Auto

**開發中（WIP）**：目前為 v11 實驗快照，不是穩定版。最高已驗證程式單局為 83 下，尚未達成 100 下；遮擋／反向仍可能誤判。錄影佇列滿仍會安全中止，尚未實作可恢復的背壓處理，不能保證每批跑滿七局。

本次依使用者要求提前備份開發進度至私人倉庫，不表示目標完成或已通過新版實戰驗證。倉庫包含程式、測試、文件及小型回歸樣本；大型錄影和本地 EXE 不上傳，README 中的 `dist/` 路徑是本機建置產物。

Windows 跳繩自動化實驗版本。目標為單局 100 下，目前尚未達成或驗證。

## 控制方式

只在畫面同時存在分數、剩餘生命、Jump 按鈕及自己角色的黃色標記位於隊列上方時允許視覺偵測器送出單次跳躍。
連點模式、固定加速曲線及失去視覺訊號後的自動週期補跳均已移除。
早期保留的最短間隔偵測器亦已刪除；目前只有畫面事件能發出起跳候選訊號。
每一局的控制器只在尚未進入本局時辨識選單；開始辨識本局後，生命歸零或無法確認遊玩畫面即停止。本局結束後控制器不會自行重開；七局批量入口只在前一局已安全停止且再次確認成績頁後，才啟動下一個獨立控制器。
遊戲失去焦點或按 F9 也會停止。

起跳偵測擬合移動繩子的曲線，觀察繩子進入角色腳邊的畫面位置；不根據前次間隔預定下一次點擊。
目前仍會漏判遮擋與反轉，不能視為已完成的 100 下方案。

## 執行

需要 Windows 與 Python 3.10 以上。

不使用 Python 時，只需雙擊最新的 `dist/HololiveJumpRopeBatch-v11.exe`。無參數即自動導航選單並最多測試七局，不需手動按「遊玩」。開局導航支援舊成績頁「下一步」、統計頁的「OK」、活動結算頁的第二個「下一步」及「遊玩」；需連續辨識 5–8 幀才點，選單按鍵保持 0.12 秒以避免遊戲漏接。若同一開局頁面仍持續可見，最多再重試一次；進入本局後停止操作選單。使用五個分區的細繩線共同擬合移動端點，量測中央玩家附近的繩高。每次起跳後仍需可見退離證據，不靠預定間隔。程式在結束時保留視窗，按 Enter 才關閉；MP4 與 JSON 會存於 EXE 旁的 `debug/`，此資料夾不進 Git。不要同時啟動兩個實例。尚未有實戰 100 下驗證。

v11 優先修正遮擋：用最近高置信度繩色輔助產生／排序候選，沿本幀可見細線做局部重新擬合；不以歷史曲線冒充當前證據，強新顏色不受舊繩色限制。退離重新待命要求更清楚或更深的可見弧線，兩個弱片段不能靠大幅跳位觸發。新 JSON 區分原始擬合與閘門接受的位置。录影有界緩衝由 8 增至 32 幀，仍在佇列滿／錯誤時安全停止，另記錄最大編碼耗時。完全遮擋仍不定時補跳。

保留 v10 的 `screen` 捕獲：複製可見遊戲客戶區並重用 GDI 資源。**遊戲必須保持前景、完整在螢幕內，且不可被其他視窗或浮窗覆蓋**；失焦／遮蓋／擷取中移動會停止。相容路徑為同一 EXE 加 `--capture printwindow`。v10 使用者實測約 33 FPS，捕獲中位約 18.2–18.4 ms，比 v9 約 28 FPS 改善，但仍未達 60。v11 額外幾何候選會增加辨識耗時，新實際速度和成績待測，不能承諾 60 FPS。

v9 預設捕獲目標及錄影時基為 **60 FPS**（可用 `--fps 15` 或 `--fps 30` 降低目標）。採非同步有界錄影、按整輪耗時補足捕獲間隔，並記錄捕獲／辨識／送出輸入的耗時；不是把舊影片補幀成 60 FPS。實際速度受 Windows 捕獲與遊戲影響，結束時會顯示實測幀率，不能保證達到 60。識別方面加入高幀率運動基準、分散背景證據、重複畫面與低置信度位置突跳過濾、廣域畫面突變後重新識別，以及遮擋下貼地高點的多次確認。仍保留 v8 的回彈與貼地模式待命修正，且不以顏色短暫變化直接認定新一圈。

批量入口預設最多 7 局，命令列 `--rounds` 也只接受 1–7。每局分開儲存 MP4 與 JSON，結束後另錄約 3 秒供核對成績。這是**明確啟用批量測試的例外**：只在上一局已停止、錄影已寫完、遊戲仍有焦點，且連續 5 幀辨識到成績頁「下一步」時才允許開始下一局；第 7 局結束後不再點選單。失焦、F9、超時、畫面不明或錄影錯誤都會中止，不會無限重開。批量錄影較佔空間，仍保存在被 Git 忽略的 `dist/debug/`，不會加入 Git。測試結束後雖然結果視窗會保留，但單例鎖立即釋放。

每次分析完成後清理已確認不再需要的舊測試影片、JSON 及衍生圖；目前保留最新兩批完整證據、原始參考影片及回歸樣本。尚未分析、仍需定位失誤或含達標證據的資料不刪。清理由分析時執行，EXE 不會自行刪除新錄影。

    python -m pip install -r requirements.txt
    python main_ui.py

手動進入一局後啟動；可在遊戲中按 F9 停止。GUI 的 F8 只在程式介面有焦點時有效。

    python jump_rope_bot.py --duration 120

上面的指令執行單局輸入。若要只觀察繩線候選事件，在 GUI 勾選「只觀察」，或使用 `--observe`。只執行本局，不自動下一步。

需要留存本局測試證據時，可加上 `--record debug/round.mp4`。程式會同時輸出 `debug/round.events.json`，逐幀記錄實際經過時間、候選事件、是否點擊與停止原因。影片預設時基為 60 FPS，但每個捕獲畫面只存一次，沒有插幀；捕獲不足 60 時播放會加速，請以 JSON 的 `t` 和 `performance.actual_round_fps` 為準。JSON 的 `frames[N]` 對應 MP4 第 N 幀。錄影佇列滿、編碼或完整性檢查失敗會中止批量；點擊次數依然不是遊戲分數。

如果要先做完全零輸入觀察，在專案目錄開啟 PowerShell：

    .\.venv\Scripts\python.exe tools\run_round_test.py --observe

程式會切到遊戲視窗並等待最多 120 秒。此模式由人手動按一次「遊玩」；確認遊玩 HUD 後只觀察 10 秒並停止。準備實戰時，讓遊戲停在前次結算頁、統計頁或「遊玩」入口，再執行：

    .\.venv\Scripts\python.exe tools\run_round_test.py

實戰模式開局前只辨識並依序點擊「下一步／OK／遊玩」中實際出現的頁面；未知畫面不點。確認遊玩 HUD 後永久封閉選單導航，只在這一局的實時畫面事件發出 Jump 輸入，最長 180 秒，結算或畫面失去確認時停止；本局結算後絕不再點「下一步」。F9 可緊急停止。每次會在本地 `debug/` 產生帶時間戳的 MP4 和 `.events.json`，不會覆蓋現有錄影。JSON 的 `menu_actions` 記錄開局前選單點擊；`input_times` 和逐幀 `input_t` 只記錄實際起跳滑鼠按下時刻，`round_started_t` 是確認本局畫面的時刻。實際時間以 JSON 的 `t` 為準。需要同時檢查 MP4 的遊戲分數與 JSON 的輸入時間；輸入數量不能代替遊戲分數。此測試入口尚無機器人實戰 100 下驗證。

    python jump_rope_bot.py --observe --duration 120

點擊次數只代表送出輸入，不能作為遊戲分數。100 下必須由單局結果畫面與對應紀錄驗證。

## 測試

最新 v10 四局 MP4 結算分數為 **73、59、66、75**；第五局錄到畫面 60 時因錄影佇列滿而停止，沒有結算成績，未執行第六／七局。前四局首次 result 後零起跳，五份影片編碼完整。最高已驗證 bot 分數仍為上一批的 **83**，未達 100。v11 通過 141 項測試、最新五份及上一批七局完整離線回放；細節及未解問題見 [驗證紀錄](docs/batch-v11-validation.md)。v11 尚待實戰，候選或輸入次數不是分數。

    python -m pytest -q

測試依賴安裝於 `requirements-dev.txt`；自動遊玩本身不依賴機器學習套件。

離線回放工具不會操作遊戲；debug 目錄存放本地分析影格與舊影片分析封存，不納入 Git。
測試錄影統一放在本地 `recordings/`，也不納入 Git；現有 2026-09-27 錄影已移入該資料夾。

    python tools/replay_visual_pass.py "錄影.mp4"
    python tools/scan_round_gate.py "錄影.mp4"

上述工具的預設裁切座標對應第一段提供的 1920×1080 錄影；換片時須指定實際遊戲客戶區。
新錄影可用 `--crop LEFT TOP RIGHT BOTTOM` 指定遊戲客戶區；例如 2026-09-27 的影片使用 `--crop 448 144 1773 889`。`tools/sample_video.py` 可以產生帶時間戳的接觸表，`tools/label_recorded_presses.py` 可估計影片中 Jump 按鈕的輸入時刻。這些都是離線工具，不會控制遊戲。

## 2026-09-22 驗證紀錄

- 影片 48–154 秒的 6,360 個連續畫面：遊玩 HUD 檢查皆通過；另抽查教學及選單畫面未授權輸入。
- 新曲線方法於 47–155 秒原先產生 71 個候選訊號；加入低信心中斷本次判定後為 49 個。這些不是遊戲分數或成功次數；仍有漏判與疑似誤判。
- 後續納入金色和粉紅色繩線，改用繩線進入腳邊位置判定，並要求連續兩張畫面確認繩線靠近。離線回放產生 51 個候選訊號；這依然不足以證明達到 100 下。
- 曾測試鄰近角色的起跳，但其外觀和身份每局隨機，且訊號有重複與漏判；該固定角色辨識實驗已移除。
- 從 Jump 按鈕動畫擷取 92 個可能的玩家按鍵時刻，與影片最後 91 分接近；現有繩線候選訊號僅對上其中 37 個，主要漏在金色、粉紅色及道具遮擋階段。
- 98–102 秒角色被擊出隊列時 HUD 仍顯示遊玩。新增自己角色的標記位置檢查；影片抽樣 2,160 幀中有 139 幀暫停輸入，其中 98.6–102 秒為 56 幀。
- 18 項單元測試通過，涵蓋禁止連點設定、結算鎖止、角色離隊、失焦停止、只觀察模式、變速視覺事件與滑鼠釋放；不代表真實遊戲成功率。
- 尚未完成新版的即時單局測試；尚未達成 100 下。不以影片中的歷史最高紀錄作為程式成果。
