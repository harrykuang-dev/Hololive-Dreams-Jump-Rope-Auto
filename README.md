# Hololive Dreams Jump Rope Auto

Windows 跳繩自動化實驗版本。目標為單局 100 下，目前尚未達成或驗證。

## 控制方式

只在畫面同時存在分數、剩餘生命、Jump 按鈕及自己角色的黃色標記位於隊列上方時允許視覺偵測器送出單次跳躍。
連點模式、固定加速曲線及失去視覺訊號後的自動週期補跳均已移除。
早期保留的最短間隔偵測器亦已刪除；目前只有畫面事件能發出起跳候選訊號。
開始辨識本局後，生命歸零或無法確認遊玩畫面即停止；不會自動點擊結算、下一步或重新開局。
遊戲失去焦點或按 F9 也會停止。

起跳偵測擬合移動繩子的曲線，觀察繩子進入角色腳邊的畫面位置；不根據前次間隔預定下一次點擊。
目前仍會漏判遮擋與反轉，不能視為已完成的 100 下方案。預設執行單局輸入；可選擇只觀察。

## 執行

需要 Windows 與 Python 3.10 以上。

    python -m pip install -r requirements.txt
    python main_ui.py

手動進入一局後啟動；可在遊戲中按 F9 停止。GUI 的 F8 只在程式介面有焦點時有效。

    python jump_rope_bot.py --duration 120

上面的指令執行單局輸入。若要只觀察繩線候選事件，在 GUI 勾選「只觀察」，或使用 `--observe`。只執行本局，不自動下一步。

    python jump_rope_bot.py --observe --duration 120

點擊次數只代表送出輸入，不能作為遊戲分數。100 下必須由單局結果畫面與對應紀錄驗證。

## 測試

    python -m pytest -q

測試依賴安裝於 `requirements-dev.txt`；自動遊玩本身不依賴機器學習套件。

離線回放工具不會操作遊戲；debug 目錄存放本地分析影格，不納入 Git。

    python tools/replay_visual_pass.py "錄影.mp4"
    python tools/scan_round_gate.py "錄影.mp4"

上述工具的預設裁切座標對應第一段提供的 1920×1080 錄影；換片時須指定實際遊戲客戶區。
新錄影可用 `--crop LEFT TOP RIGHT BOTTOM` 指定遊戲客戶區；例如 2026-09-27 的影片使用 `--crop 448 144 1773 889`。`tools/sample_video.py` 可以產生帶時間戳的接觸表，`tools/label_recorded_presses.py` 可估計影片中 Jump 按鈕的輸入時刻。這些都是離線工具，不會控制遊戲。

## 2026-09-22 驗證紀錄

- 影片 48–154 秒的 6,360 個連續畫面：遊玩 HUD 檢查皆通過；另抽查教學及選單畫面未授權輸入。
- 新曲線方法於 47–155 秒原先產生 71 個候選訊號；加入低信心中斷本次判定後為 49 個。這些不是遊戲分數或成功次數；仍有漏判與疑似誤判。
- 後續納入金色和粉紅色繩線，改用繩線進入腳邊位置判定，並要求連續兩張畫面確認繩線靠近。離線回放產生 51 個候選訊號；這依然不足以證明達到 100 下。
- 曾測試鄰近角色的起跳，但其外觀和身份每局隨機，且訊號有重複與漏判；該固定角色辨識實驗已移除。
- 從 Jump 按鈕動畫擷取 92 個可能的玩家按鍵時刻，與影片最後 91 分接近；現有繩線候選訊號僅對上其中 37 個，主要漏在金色、粉紅色及道具遮擋階段。
- 98–102 秒角色被擊出隊列時 HUD 仍顯示遊玩。新增自己角色的標記位置檢查；影片抽樣 2,160 幀中有 139 幀暫停輸入，其中 98.6–102 秒為 56 幀。
- 18 項單元測試通過，涵蓋禁止連點設定、結算鎖止、角色離隊、失焦停止、只觀察模式、變速視覺事件與滑鼠釋放；不代表真實遊戲成功率。
- 尚未完成新版的即時單局測試；尚未達成 100 下。不以影片中的歷史最高紀錄作為程式成果。

## 2026-09-27 新錄影驗證

- 新提供的錄影長約 159.77 秒，結果畫面顯示 132 下；這是錄影中的成績，並非本程式達成的成績。
- 在 16–153 秒的 8,220 幀中，HUD 檢查全部通過；中央玩家的黃色標記有 299 幀無法確認，因此那段時間程式會暫停輸入。
- 從 Jump 按鈕動畫估計 133 個可能的輸入時刻，與畫面結果的 132 分接近。現有視覺偵測器僅產生 57 個候選，當中 36 個在估計輸入時刻附近；漏判與誤判仍多，尤其在道具、燈光、繩線換色階段。
- 放寬色彩遮罩、調整交叉門檻及加入細線對比特徵的離線實驗，未能在後段同時保持足夠召回率和低誤判。因此沒有把寬鬆門檻加入自動點擊邏輯，也沒有把錄影中的 132 分視作程式驗證。
