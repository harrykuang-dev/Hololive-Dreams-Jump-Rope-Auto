# Hololive Dreams Auto Jump Rope

[English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Indonesian](README.id.md) · [简体中文](README.zh-CN.md)

Windows 版《hololive Dreams》的自动跳绳程序。通过游戏画面识别绳子位置，以一般鼠标输入控制起跳，并在结算后接续下一局。

## 下载

从 [Releases](https://github.com/harrykuang-dev/Hololive-Dreams-Jump-Rope-Auto/releases/latest) 下载 **1.3.2** 完整 Windows x64 `.7z` 包并解压。包内包含 TensorRT 10.13 和 DirectML；兼容的 NVIDIA 环境自动使用 TensorRT FP16，其他支持的 GPU 使用 DirectML。

保留 EXE、`_internal/` 和 `accelerators/`。运行程序不使用 PyTorch。首次使用 TensorRT 时，程序会在开始游戏操作前为本机 GPU 构建并缓存引擎，可能需要数分钟。

上一版源代码和 MIT 许可证保存在 [archive/v1.2.1](archive/v1.2.1/)。

## 功能

- 停止分数可选“不限”或自定义 1–999。确认 HUD 分数达标后停止跳跃，等待本局结算，再按目标局数继续下一局。
- 追踪绳子运动，识别起跳时机并自动跳绳。
- 起跳滑条提供 −40～+40 ms 连续时间偏移，同时调整圆周与扫地起跳；中央保留默认策略，负值提前、正值推迟。单击 0 或滑轨中央归零，其他刻度不吸附。
- 识别开始与结算菜单，确认上一局结束后接续游玩。
- 支持六种界面语言：繁體中文、简体中文、English、日本語、한국어、Indonesian。选择语言会切换程序界面，不会修改游戏设置。
- 可设置目标局数，达到目标后停止。
- 开始快捷键默认 F8，停止快捷键默认 F9。点击设置框，再按下新按键或组合键即可自定义，两者不能相同。
- 提供运行记录，以及可选的本机开发者诊断模式。

## 使用方法

1. 打开游戏，进入跳绳开始画面或结算画面。
2. 运行 EXE，在“语言/Language”中选择程序语言。
3. 设置目标局数（1–999，默认 1 局）；需要更换快捷键时，点击设置框并按下要使用的按键。
4. 点击“开始”或按开始快捷键。程序会尝试切回游戏；运行时请保持游戏前台、完整位于主屏幕内且无遮挡。建议选用深色、短发、装饰少的角色和配饰，例如 **儒乌风亭螺钿（默认服饰）** 配像素太阳眼镜（pixel sunglasses）。
5. 按停止快捷键或点击“停止”即可停止。游戏失焦时会尝试切回，每批最多恢复一次；需要切换其他程序时，请先停止。

## 使用条件与限制

程序仅使用 GPU 推理。完整包包含 TensorRT 10.13 及 ONNX Runtime DirectML；兼容的 NVIDIA 环境自动使用 TensorRT FP16，否则使用支持 DirectX 12 的硬件显卡运行 DirectML。

适用于 Windows 10／11 x64 及 Windows 版游戏。游戏客户区需保持 16:9；运行时不要最小化、遮挡或移动窗口。

在确保游戏稳定 60 帧的情况下，尽可能调高画面设置。

界面中的“起跳输入”是操作次数，实际成绩请查看游戏结算画面。识别可能受角色配色、动画、分辨率、电脑性能及游戏更新影响；遇到异常请停止并提供诊断资料。

## 技术实现

完整游戏客户区以保持比例的 letterbox 缩放至 640×640。一个 YOLO26n Detect 模型同时识别可见绳子的外框与主角三角标记。同一批权重由 TensorRT 10.13 FP16 或 ONNX Runtime DirectML 在硬件 GPU 上推理，不使用 CPU 模型推理。

[时序控制器](controller/policy.py)结合连续外框边界、运动、真实帧间隔及各形态的参考运动轮廓，估计下一次可见过绳事件。主角标记与实际按键历史用于判断空中、落地及能否再次起跳。局部框只作局部证据，不补画被遮挡的绳子；已稳定建立的短期预约可延续有限遮挡，圆周时机另按估计速度调整。

[起跳滑条](timing_control.py)连续偏移圆周与扫地的操作窗口及预约，范围 −40～+40 ms；中央使用默认时机，点击 0 或滑轨中央归零。

[停止分数](score_limit.py)从同一张捕获画面读取 HUD 数字，通过重复可信读数及分数增量检查确认达标。达标后取消预约并释放输入，等待正常结算；“不限”不执行分数识别。

[控制循环](jump_rope_bot.py)只使用一个 DXGI 捕获器及一个输入所有者。独立、可中断计时器在目标 25 ms 后松开，按住期间继续观察。实际按下前重新检查前景、窗口尺寸、停止请求及来源画面编号；保留过绳时间窗和有界遮挡预测，开始与结算菜单使用不依赖文字的几何及颜色检查。

## 异常反馈与开发者模式

无法续局、起跳异常或其他问题，可在 [GitHub Issues](https://github.com/harrykuang-dev/Hololive-Dreams-Jump-Rope-Auto/issues) 提交反馈。

勾选“开发者模式”后再复现问题。它会保存诊断截图、逐帧识别记录、按键时序及耗时；资料只存于本机，不会自动上传。启用后会增加性能负担。

点击右侧 `?` 可查看并打开诊断文件夹：

```text
%LOCALAPPDATA%\HololiveJumpRopeAuto\sessions\
```

每次运行建立以时间命名的文件夹，所有局数的文本诊断集中于一份 `diagnostics.json`，另存诊断图片。运行结束后生成 `diagnostics.zip`，包含这份 JSON 及保留的图片；初始化在取得画面前失败时也会保存。

诊断包含显卡与驱动、实际推理后端与回退错误、捕获及推理耗时、识别与起跳判断、原生输入时序、抢走焦点的窗口标题与进程名称，以及停止原因。反馈时请附上本次运行的 ZIP 及问题描述。
