# Hololive Dreams Auto Jump Rope — 1.0

[繁體中文](README.md) · [简体中文](README.zh-CN.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Indonesian](README.id.md)

Windows 版《hololive Dreams》的自动跳绳程序。通过游戏画面识别绳子位置，以一般鼠标输入控制起跳，并在结算后接续下一局。

## 下载

前往 [GitHub Releases](https://github.com/harrykuang-dev/Hololive-Dreams-Jump-Rope-Auto/releases/tag/v1.0)，下载附件中的 `HololiveDreamsJumpRopeAuto-1.0.exe`。

只需运行这一个 EXE，无需安装 Python。Release 附有 SHA-256 校验文件；源码 ZIP 需要自行构建。

## 功能

- 追踪绳子运动，识别起跳时机并自动跳绳。
- 识别开始与结算菜单，确认上一局结束后接续游玩。
- 支持六种界面语言：繁體中文、简体中文、English、日本語、한국어、Indonesian。选择语言会切换程序界面，不会修改游戏设置。
- 可设置目标局数，达到目标后停止；每次开始都重新计数。
- 开始快捷键默认 F8，停止快捷键默认 F9。点击设置框，再按下新按键或组合键即可自定义，两者不能相同。
- 提供运行记录，以及可选的本机开发者诊断模式。

## 使用方法

1. 打开游戏，进入跳绳开始画面或结算画面。
2. 运行 EXE，在“语言/Language”中选择程序语言。
3. 设置目标局数（1–999，默认 1 局）；需要更换快捷键时，点击设置框并按下要使用的按键。
4. 点击“开始”或按开始快捷键。程序会尝试切回游戏；运行时请保持游戏前台、完整位于主屏幕内且无遮挡。建议选用深色、短发、装饰少的角色和配饰，例如 **儒乌风亭螺钿（默认服饰）** 配像素太阳眼镜（pixel sunglasses）。
5. 按停止快捷键、点击“停止”，或切换窗口即可停止。再次开始会重新计数。

## 使用条件与限制

适用于 Windows 10／11 x64 及 Windows 版游戏。游戏客户区需保持 16:9；运行时不要最小化、遮挡或移动窗口。不支持后台游玩，也不会在换日登出后自动重新登录。

在确保游戏稳定 60 帧的情况下，尽可能调高画面设置。

界面中的“起跳输入”是操作次数，实际成绩请查看游戏结算画面。识别可能受角色配色、动画、分辨率、电脑性能及游戏更新影响；遇到异常请停止并提供诊断资料。

### 双显卡捕获错误

若开始时出现 `-2005270524 / 0x887A0004`（指定的设备接口或功能级别不受支持），请调整程序的 GPU 偏好：

![DXGI 捕获错误提示](docs/dxgi-unsupported-error.png)

1. 在 Windows“设置 → 系统 → 显示 → 高级显示”中选择游戏使用的主屏幕，查看“连接到”的显卡名称。
2. 返回“显示 → 图形”（Windows 10 为“图形设置”），添加桌面应用，浏览并加入实际运行的 `HololiveDreamsJumpRopeAuto-1.0.exe`。
3. 打开该程序的“选项／GPU 首选项”，选择上述显卡并保存。“节能”通常对应集显，“高性能”通常对应独显；以显示的显卡名称为准。
4. 完全关闭程序后重新打开，再点击“开始”测试。

此设置适用于程序 EXE。内置与外接屏幕、独显直连及混合模式可能使用不同的输出显卡，应根据当前屏幕的连接信息选择。若仍失败，请开启开发者模式复现一次，并提供该次运行文件夹中的 `session.log`、显卡型号及屏幕连接信息。

## 技术实现

### 画面捕获与处理

[捕获模块](vision.py)通过 DXGI／DXcam 获取游戏客户区的新画面，每次捕获前后检查前台、位置、尺寸及遮挡。控制循环目标为 60 FPS，实际速度取决于游戏新画面、识别耗时与系统调度。没有新画面时不沿用旧画面起跳；等待空档达到 100ms 后恢复会丢弃跨空档帧并重建识别器，最多等待 500ms，仍无新画面则停止。

[区域处理](priority.py)以 960×540 为识别基准，先裁出采样范围再按相同比例缩放。裁剪边界按输入与输出分辨率的整数比例对齐，维持原有缩放采样位置，同时减少不需要的像素运算。

### 绳线识别与几何拟合

[追踪器](candidate_tracker.py)在五个横向区段中取共 100 个采样列，利用 HSV 筛选蓝紫、金黄、粉色及亮白候选，再结合帧间移动和细线的明暗特征排除背景。从不同区段选取点组，求解多条二次曲线，依沿线支持度及跨区段分布评分，选出符合当前画面的绳子弧线。高可信观察也会更新绳子配色，协助后续追踪。

弧线会换算成角色位置上的相对高度，并记录可见支持比例、主要颜色和移动方向。角色或道具遮挡中央时，可见的两侧片段仍能约束拟合；若证据不足，程序保留必要状态等待重新观察，不按固定周期盲跳。

### 起跳判断与遮挡恢复

[识别器](jump_detector.py)结合弧线接近、跨线、退离及低位绳转折等画面状态，判断一次过绳是否已触发。遮挡后重新允许起跳时，会检查连续可见片段、两侧支持及高度变化，避免同一次过绳重复触发。

防突变检查把“上次实际观察”与“上次接受位置”的时间分开。部分支持的拟合若突然朝角色靠近，不会仅因保留位置的时间变旧而放行；最近三次原始观察若显示可信、连贯的接近，则可回到正常判断。

### 输入、菜单与续局

[控制器](jump_rope_bot.py)产生起跳候选后，先再取一张新画面确认游戏仍在进行、角色可以操作及起跳按钮可见，再把相对坐标转换成实际屏幕位置，通过 Windows 鼠标输入按下 25ms。即使输入途中中断，也会释放鼠标；实际按住时长会记入诊断资料，可能受系统调度影响。

菜单按钮依位置、青色胶囊外框、白色边缘及页面配色识别，排除内部文字。导航要求多帧确认并限制同页重试；首次确认游戏 HUD 后，该局停止菜单导航。[会话控制](batch_session.py)只在上一局结束且结算页稳定确认后开下一局，达到目标局数即停止。程序依据画面与一般输入运行，不读取或修改游戏程序内存、存档或游戏文件。

## 异常反馈与开发者模式

无法续局、起跳异常或其他问题，可在 [GitHub Issues](https://github.com/harrykuang-dev/Hololive-Dreams-Jump-Rope-Auto/issues) 提交反馈。

勾选“开发者模式”后再复现问题。它会保存诊断截图、逐帧识别记录、按键时序及耗时；资料只存于本机，不会自动上传。启用后会增加性能负担。

点击右侧 `?` 可查看并打开诊断文件夹：

```text
%LOCALAPPDATA%\HololiveJumpRopeAuto\sessions\
```

每次运行建立以时间命名的文件夹，每局结束后在 `round-局号` 文件夹中生成 `diagnostics.zip`。反馈时请提供程序版本、游戏语言／角色、分辨率、Windows 显示缩放、问题描述，以及出问题那一局的诊断 ZIP。
