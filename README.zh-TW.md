# Hololive Dreams Auto Jump Rope

[English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Indonesian](README.id.md) · [简体中文](README.zh-CN.md)

Windows 版《hololive Dreams》的自動跳繩程式。透過遊戲畫面辨識繩子位置，以一般滑鼠輸入控制起跳，並在結算後接續下一局。

## 下載

從 [Releases](https://github.com/harrykuang-dev/Hololive-Dreams-Jump-Rope-Auto/releases/latest) 下載 **1.3.3** 完整 Windows x64 `.7z` 包並解壓。包內包含 TensorRT 10.13 及 DirectML；相容的 NVIDIA 環境自動使用 TensorRT FP16，其他支援的 GPU 使用 DirectML。

保留 EXE、`_internal/` 及 `accelerators/`。玩家端不使用 PyTorch。首次使用 TensorRT 時，程式會在開始遊戲操作前為本機 GPU 建立並快取引擎，可能需要數分鐘。

前一版原始碼及 MIT 授權保存在 [archive/v1.2.1](archive/v1.2.1/)。

## 功能

- 停止分數可選「不限」或自訂 1–999。確認 HUD 分數達標後停止跳躍，等待本局結算，再依目標局數接續下一局。
- 追蹤繩子運動，辨識起跳時機並自動跳繩。
- 起跳滑條提供 −40～+40 ms 連續時間偏移，同時調整圓周與掃地起跳；中央保留預設策略，負值提早、正值推遲。單擊 0 或滑軌中央歸零，其餘刻度不吸附。
- 辨識開始與結算選單，確認上一局結束後接續游玩。
- 支援六種介面語言：繁體中文、简体中文、English、日本語、한국어、Indonesian。選擇語言會切換程式介面，不會修改遊戲設定。
- 可設定目標局數，達到目標後停止。
- 開始快捷鍵預設 F8，停止快捷鍵預設 F9。點擊設定框，再按下新按鍵或組合鍵即可自訂，兩者不能相同。
- 提供執行記錄，以及可選的本機開發者診斷模式。

## 使用方法

1. 開啟遊戲，進入跳繩開始畫面或結算畫面。
2. 執行 EXE，在「語言/Language」中選擇程式語言。
3. 設定目標局數（1–999，預設 1 局）；需要更換快捷鍵時，點擊設定框並按下要使用的按鍵。
4. 點擊「開始」或按開始快捷鍵。程式會嘗試切回遊戲；運行時請保持遊戲前景、完整位於主螢幕內且無遮擋。建議選用深色、短髮、裝飾少的角色和配飾，例如 **儒烏風亭螺鈿（預設服飾）** 配 像素太陽眼睛（pixel sunglasses）。
5. 按停止快捷鍵或點擊「停止」即可停止。遊戲失焦時會嘗試切回，每批最多恢復一次；需要切換其他程式時，請先停止。

## 使用條件與限制

程式僅使用 GPU 推論。完整包包含 TensorRT 10.13 及 ONNX Runtime DirectML；相容的 NVIDIA 環境自動使用 TensorRT FP16，否則使用支援 DirectX 12 的硬體顯示卡執行 DirectML。

適用於 Windows 10／11 x64 及 Windows 版遊戲。遊戲客戶區需維持 16:9；運行時不要最小化、遮擋或移動視窗。

在確保遊戲穩定 60 幀的情況下，盡可能調高畫面設定。

介面中的「起跳輸入」是操作次數，實際成績請查看遊戲結算畫面。辨識可能受角色配色、動畫、解析度、電腦效能及遊戲更新影響；遇到異常請停止並提供診斷資料。

## 技術實現

完整遊戲客戶區以保持比例的 letterbox 縮放至 640×640。一個 YOLO26n Detect 模型同時辨識可見繩子的外框與主角三角標記。同一批權重由 TensorRT 10.13 FP16 或 ONNX Runtime DirectML 在硬體 GPU 上推論，不使用 CPU 模型推論。

[時序控制器](controller/policy.py)結合連續外框邊界、運動、真實影格間隔及各形態的參考運動輪廓，估計下一次可見過繩事件。主角標記與實際按鍵歷史用於判斷空中、落地及能否再次起跳。局部框只作局部證據，不補畫被遮擋的繩子；已穩定建立的短期預約可延續有限遮擋，圓周時機另按估計速度調整。

[起跳滑條](timing_control.py)連續偏移圓周與掃地的操作窗口及預約，範圍 −40～+40 ms；中央使用預設時機，點擊 0 或滑軌中央歸零。

[停止分數](score_limit.py)從同一張擷取畫面讀取 HUD 數字，透過重複可信讀數及分數增量檢查確認達標。達標後取消預約並釋放輸入，等待正常結算；「不限」不執行分數辨識。

[控制迴圈](jump_rope_bot.py)只使用一個 DXGI 擷取器及一個輸入擁有者。獨立、可中斷計時器在目標 25 ms 後放開，按住期間繼續觀察。實際按下前重新檢查前景、視窗尺寸、停止要求及來源畫面編號；保留過繩時間窗與有界遮擋預測，開始與結算選單使用不依賴文字的幾何及顏色檢查。

## 異常回報與開發者模式

無法續局、起跳異常或其他問題，可在 [GitHub Issues](https://github.com/harrykuang-dev/Hololive-Dreams-Jump-Rope-Auto/issues) 提交回報。

勾選「開發者模式」後再重現問題。它會保存診斷截圖、逐幀識別記錄、按鍵時序及耗時；資料只存於本機，不會自動上傳。啟用後會增加效能負擔。

點擊右側 `?` 可查看並開啟診斷資料夾：

```text
%LOCALAPPDATA%\HololiveJumpRopeAuto\sessions\
```

每次執行建立以時間命名的資料夾，所有局數的文字診斷集中於一份 `diagnostics.json`，另存診斷圖片。執行結束後產生 `diagnostics.zip`，包含這份 JSON 及保留的圖片；初始化在取得畫面前失敗時也會保存。

診斷包含顯卡與驅動、實際推論後端與回退錯誤、擷取及推論耗時、識別與起跳判斷、原生輸入時序、搶走焦點的視窗標題與程序名稱，以及停止原因。回報時請附上本次執行的 ZIP 及問題描述。
