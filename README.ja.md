# Hololive Dreams Auto Jump Rope

[English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Indonesian](README.id.md) · [简体中文](README.zh-CN.md)

Windows 版『hololive Dreams』の自動なわとびプログラムです。ゲーム画面から縄の位置を認識し、通常のマウス入力でジャンプを操作します。結果画面の確認後は次のプレイへ進みます。

## ダウンロード

[Releases](https://github.com/harrykuang-dev/Hololive-Dreams-Jump-Rope-Auto/releases/latest) から **1.3.2** の Windows x64 完全版 `.7z` パッケージをダウンロードして展開してください。TensorRT 10.13 と DirectML を同梱し、対応する NVIDIA 環境では TensorRT FP16、それ以外の対応 GPU では DirectML を自動的に使用します。

EXE、`_internal/`、`accelerators/` を同じ場所に保持してください。実行時に PyTorch は使用しません。TensorRT の初回起動時は、ゲーム操作を始める前にローカル GPU 用のエンジンを構築してキャッシュするため、数分かかる場合があります。

旧版のソースコードと MIT ライセンスは [archive/v1.2.1](archive/v1.2.1/) に保存しています。

## 機能

- 停止スコアは「無制限」または1～999を指定できます。HUDで到達を確認するとジャンプを止め、ラウンド終了後に設定したラウンド数まで続けます。
- 縄の動きを追跡し、ジャンプのタイミングを自動判定します。
- ジャンプ時刻を −40～+40 ms の範囲で連続調整できます。回転と地面を掃く動作の両方に適用され、中央は既定値です。負は早め、正は遅めです。0 またはレール中央をクリックするとリセットされます。
- 開始・結果画面のメニューを認識し、プレイ終了後に続行します。
- 繁体字中国語、簡体字中国語、英語、日本語、韓国語、インドネシア語の六つの表示言語に対応します。プログラムの言語変更はゲーム設定を変更しません。
- 目標回数を設定でき、到達すると停止します。
- 初期ショートカットは開始 F8、停止 F9 です。設定欄をクリックしてキーやキーの組み合わせを押すと変更できます。開始と停止には異なるキーを設定してください。
- 実行履歴と、任意で有効にできるローカル診断モードを備えています。

## 使い方

1. ゲームでなわとびの開始画面または結果画面を開きます。
2. EXE を実行し、「言語/Language」で表示言語を選びます。
3. 目標回数を 1–999 回に設定します。初期値は 1 回です。ショートカットを変更する場合は設定欄をクリックして希望のキーを押します。
4. 開始ボタンまたは開始ショートカットを押します。プログラムはゲームを前面に切り替えようとします。ゲーム全体をメインモニター内に表示し、ほかのウィンドウで隠さないでください。暗い色で短髪、装飾やアクセサリーの少ないキャラクターがおすすめです。例：**儒烏風亭らでん（デフォルト衣装）**とピクセルサングラス（pixel sunglasses）。
5. 停止ショートカットまたは停止ボタンで停止します。ゲームが非アクティブになると、1回の実行につき最大1回まで前面への復帰を試みます。別のプログラムへ切り替える前に停止してください。

## 動作条件と制限

GPU推論のみを使用します。完全版パッケージにはTensorRT 10.13とONNX Runtime DirectMLが含まれます。対応するNVIDIA環境ではTensorRT FP16を自動選択し、それ以外は対応するDirectX 12ハードウェアGPUでDirectMLを実行します。

Windows 10／11 x64 と Windows 版ゲームが必要です。ゲームのクライアント領域を 16:9 に保ち、動作中に最小化・遮蔽・移動しないでください。

ゲームが安定して 60 FPS を維持できる範囲で、画質設定をできるだけ高くしてください。

画面の「ジャンプ入力」は入力回数です。実際の得点はゲームの結果画面で確認してください。キャラクターの色、アニメーション、解像度、PC の性能やゲーム更新が認識に影響する場合があります。問題が起きたら停止し、診断データを提供してください。

## 技術実装

ゲームのクライアント領域全体を、縦横比を維持した letterbox で 640×640 に変換します。1つの YOLO26n Detect モデルで、見えている縄の外接矩形とプレイヤーの三角マーカーを認識します。同じ学習済み重みを TensorRT 10.13 FP16 または ONNX Runtime DirectML でハードウェア GPU 上で実行し、CPU によるモデル推論は行いません。

[時系列制御](controller/policy.py)は、連続する矩形の境界、動き、実際のフレーム間隔、形態ごとの参照動作から次の縄の通過を推定します。マーカーと入力履歴から空中・着地状態を確認します。部分的な矩形は部分的な証拠として扱い、隠れた縄は補完しません。安定した短期予約のみを限定的な遮蔽中に維持し、円運動のタイミングは推定速度に合わせて調整します。

[スライダー](timing_control.py)は円運動と地面を掃く動作の入力範囲・予約を −40～+40 ms で連続調整します。中央が標準で、0 または軌道中央のクリックで戻ります。

[停止スコア](score_limit.py)は同じ取得画像の HUD 数字を読み、複数の確実な読み取りと増分チェックで到達を確認します。到達後は予約と入力を解除し、通常の結果画面を待ちます。「無制限」ではスコアを認識しません。

[制御ループ](jump_rope_bot.py)は1つの DXGI キャプチャーと1つの入力制御を使用します。独立した中断可能タイマーが目標 25 ms 後に離し、その間も観察を続けます。押下直前に前面状態、サイズ、停止要求、取得画像の識別番号を再確認します。通過タイミングの許容範囲と遮蔽時の予測期限は維持します。開始・結果メニューは文字に依存しない形状と色で判定します。

## 不具合報告と開発者モード

続行やジャンプの異常などは [GitHub Issues](https://github.com/harrykuang-dev/Hololive-Dreams-Jump-Rope-Auto/issues) へ報告してください。

問題を再現する前に開発者モードを有効にすると、診断画像、フレームごとの認識記録、入力時刻と処理時間をローカルに保存します。自動アップロードは行いません。有効化すると処理負荷が増加します。

右の `?` から診断フォルダーの表示とオープンができます。

```text
%LOCALAPPDATA%\HololiveJumpRopeAuto\sessions\
```

実行ごとに日時付きのフォルダーを作成し、全ラウンドのテキスト診断を1つの `diagnostics.json` にまとめ、診断画像を別途保存します。終了時に、この JSON と保持された画像を含む `diagnostics.zip` を作成します。画像取得前に初期化が失敗した場合も保存します。

GPU・ドライバー情報、使用した推論バックエンドとフォールバックエラー、キャプチャー・推論時間、認識とジャンプ判断、入力時刻、フォーカスを奪ったウィンドウ名とプロセス名、停止理由を記録します。報告には今回の ZIP と症状を添えてください。
