## 改动及依据

- v11 第四局的完整原始测量揭示浅高点及短暂远端弧线漏判。加入连续浅高点证据，以及三张以上新鲜远端弧线、至少 45 ms 观察跨度、覆盖率与位置一致性检查。没有周期补跳。完整回归数据保存在 `tests/fixtures/gate/v11-round-4.json`。
- 录影保留 32 张内存缓冲，超过时写有界 256 MiB 无损 NPY 临时缓冲，内存和磁盘引用进入同一 FIFO。恢复编码后按原顺序写 MP4；不丢帧、不插帧、不改变 JSON 索引。真实编码错误、容量耗尽、低磁盘空间仍停止。成功排空的临时目录自动移除；失败缓冲保留供诊断。
- 新 DXGI 后端只取新帧，每次捕获前后均验证前景、无遮挡、窗口位置尺寸及主屏范围，等待中也检查 F9。没有旧帧回退或后台输入。
- 加载页可能超过 100 ms 不产生新帧，开局阶段在原 120 秒上限内继续等待；任何已见过游玩 HUD 的实战停帧仍立即停止。成绩尾录及批间只确认新取得的画面，不凭缓存计数。
- Computer Use 启动浮层只允许在首张捕获之前等待最多 20 秒；此时不返回画面或输入。实战中出现浮层仍停止。
- 游玩点击也允许在同一页持续确认后最多重试一次；观察到任何游玩 HUD 即永久封闭该局菜单。不会通过重试重新打开结束的本局。
- 每批新增 `.run.json`，记录实际 EXE 路径、SHA-256、后端、局数及录像路径，并另写 `.run.log`；不覆盖既有文件。

## 捕获及录影压力验证

没有输入的同窗口 120 次捕获基准：screen 中位 26.35 ms／P95 28.32 ms，DXGI 中位 7.35 ms／P95 19.39 ms。不同桌面新帧的游戏区域仍可能相同，不能据此保证实战 60 FPS。两种输出均人工核对正确客户区与 BGR 颜色。

`tools/stress_recording.py` 离线生成七轮、每轮 180 张 960×540 像素画面，按 60 FPS 送入。每轮编码起始延迟 0.85 秒，偶数轮另有每张 20 ms 编码延迟。七轮全部解码核对 FIFO 顺序、帧数及 JSON 映射；磁盘溢出 19–87 张，最长单次写盘 7.34 ms。它证明这些有限压力条件下能恢复，不证明任意磁盘或持续拥塞都能恢复。
