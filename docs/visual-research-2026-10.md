# 2026-10 纯画面研究验证

用户授权继续研究工具并改进视觉跳绳，但要求成品不包含解包内容，仍由输入画面决定起跳；不得补充或修改能量。研究环境与下载文件仅保留本机，详见[研究与成品边界](research-boundary.md)。以下候选没有引入内部动画、碰撞数据或解包模板。

## 候选与离线验证

v22 在既有绳形识别中加入较窄的上下像素对比，排除宽彩色表面，同时保留白色发光绳。直接对所有颜色使用窄滤波会丢失真实发光绳，已放弃。v23 用 OpenCV 无符号饱和减法实现相同判定，起跳门控与时机阈值不变。独立合成图验证宽彩色曲线被拒绝、白色发光绳仍保留。

随机像素验证两种实现的布尔判定一致。局部谓词微基准中位耗时约 2.05 → 0.10 ms，这只衡量该谓词，不能当作整机 FPS。历史两段完整压缩录像的顺序回放保留同等候选数量，但部分候选时间发生变化；压缩画面与原始检测量测不同，因此不把离线候选当作实际成绩或已修复失误。

## 完整实战

测试于 2026-10-06 至 07 完成，启动时游戏显示 1.2.1。原发布 EXE 的 SHA-256 与 0.1.0 发布记录一致。三批均独立执行七局，分数人工读取结算画面，输入次数不作为分数。

| 版本 | 七局结算 | 达到100 | 最低 | 中位数 |
| --- | --- | --- | --- | --- |
| v22 | 79 / 97 / 70 / 75 / 82 / 93 / 81 | 0 | 70 | 81 |
| v23 | 108 / 98 / 96 / 90 / 94 / 67 / 81 | 1 | 67 | 94 |
| 原发布版同期对照 | 92 / 76 / 77 / 91 / 72 / 121 / 66 | 1 | 66 | 77 |

v23 相比这一批同期对照中位数提高17、最低提高1，满足旧记录中“中位数提高10且最低不下降”的数值门槛。但测试是顺序运行的单批比较，场景随机，不是重复、交错或配对试验，不能据此确认因果或可重复改善。相比历史最佳 v18b 的最低78、中位数91，v23 的最低明显下降；没有实现七局稳定100。

v23 首局实际捕获48.57 FPS、检测耗时中位12.40 ms；原版同期首局52.62 FPS、检测耗时中位10.59 ms。局部谓词提速没有消除新滤波整体开销，场景差异也可能影响耗时。

三批21局全部 `round_finished`、`error=null`、编码完整，MP4元数据帧数与事件帧数一致，末帧可解码，结果后零起跳、开局后零菜单输入。帧数审计不是每个视频字节的完整解码审计。v22、v23 界面已核对7/7并停止，第七局后不继续导航。没有点击能量恢复、BOOST、MODE、购买或道具入口。

## 保留与下一步

默认 `rope_track.py` 恢复到发布基准。v23 及其两项合成图测试独立归档到 `experiments/rope_track_v23.py` 和 `tests/test_archived_surface_filter.py`，应用不导入，EXE不打包。v22 与 v23 的原始录像、输入日志、扣血窗口和研究资料仅保留本机，未上传。

v22 第三局与 v23 第六局的扣血片段显示，夜景蓝色道具局部遮挡下仍有绳形突然跳位和漏跳。细线过滤不能独自解决这一问题。后续应先针对这些当前画面证据比较分区拟合的连续性与遮挡后重新获取，保持当前可见绳形要求，不能用内部动画或失去视觉后的定时补跳替代。

归档后206项非界面测试通过（包含归档候选测试），六项界面测试本轮未重跑，界面代码未改变。新封装边界检查核对原发布EXE的八个冻结模块及六项既有资源，与恢复后的源码一致，研究依赖、资源及归档候选均未打包。原0.1.0发布文件未替换；本轮不发布新的EXE。
