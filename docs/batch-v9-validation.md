## v9 修改

- 捕獲目標 60 FPS，用整輪耗時決定剩餘等待，移除工作完成後固定再等 12 ms；
  這只安排捕獲，不安排起跳。未改用新的 Windows 捕獲後端，因此不保證實測 60。
- 錄影改為背景執行緒、8 幀有界佇列及最多 960 像素寬；一個捕獲畫面只存一次，
  `frames[N]` 對應 MP4 第 N 幀。預設 MP4 時基 60，實測不足會快放，必須按 JSON t 分析。
- 佇列满、編碼異常、尾段失敗、最終幀數不符均停止；不得默默丟掉證據並繼續下一局。
- 記錄捕獲、HUD、繩線、起跳前複查耗時及輸入延遲，另統計重複畫面、換景重取和實際 FPS。
- 高幀率用約 50 ms 的已觀察畫面基準辨別微小運動；背景證據約每 45 ms 採一次，
  防止短暫道具在密集幀中被當成多個獨立確認。過線仍逐個新畫面檢查，不靠節奏補跳。
- 廣域突變清掉舊幾何與待命狀態、等待重新看到繩；相同採樣像素不重複累積證據。
  此方法未證明能識別所有漸變換景，也可能把強閃光當突變，須實戰檢查漏判代價。
- 遮擋中的貼地高點可由 3 個分散、置信度 ≥.35 的高點量測建立，保留強證據舊路徑。
- 強上方繩弧證據在模式清空時保留，防止同一弧近端變金色後被當成新貼地圈。
  高幀率下低置信度幾何的單幀大突跳先不採用，保留上一個接受位置等新證據。
