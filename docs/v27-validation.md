# V27 前端验收

控制核心为冻结 V27（speed2 + snap_clock），25ms，960×540识别，DXGI目标60fps。没有加入上一轮的确认器、歧义选择或10ms按键实验。

## 本地已验证

- 核心五个源文件与冻结版本逐字节相同；整个控制器除模块入口、诊断适配与诊断对象引用外相同。
- 捕获、新鲜帧恢复、RoundGate、玩家标记、起跳位置、启动导航封闭与重试规则相同。首次看到游戏HUD后，该局不会再调用按钮识别。
- 既有72、124、104分三局的16,940次原始BGR采样列重播：候选、判定原因均零差异。这是观察判定回放，不是新的鼠标输入／游戏得分测试。
- 按钮识别不依赖文字。现有中文页面、六种文字合成变体、空文字、未知页面、按钮移位／缺失及0.8–1.05倍大小均通过。
- 六种前端语言和96／120／144／192 DPI布局、快捷键捕获、旧快捷键队列丢弃、运行中控制锁定通过模拟会话测试。
- 默认关闭开发者模式时，前端启动不导入诊断或压缩模块。

## 实机验收待做

上述证据确认起跳算法没有改变，不能声称新前端已实测相同平均分；也不能把中文页面的合成文字变化视为六种真实游戏语言已全部实测。

建议用同一窗口／分辨率运行新前端10局：

1. 关闭旧测试程序，打开 `HololiveDreamsJumpRopeAuto-1.0.exe`。
2. 局数设10，开启开发者模式，进入跳绳准备页或成绩页后按F8。保持游戏前景。
3. 正常完成后保留整个会话目录。每局结算保存在最后诊断图中，分析时核对游戏真实分数，不能用输入次数替代。
4. 与既有V27十局数据比较，不重复运行旧参数候选。基准平均97.1、中位数100、低于80分1局；这些是历史资料，非同时对照。
5. 另在实际游戏语言切换后各确认至少一次完整“成绩→确认→活动→游玩”流程。助手的介面语言选择不会切换游戏语言。

若新前端出现实机退步，先检查实际识别帧率、捕获空档、起跳延迟、掉心前后密集截图和诊断图，再决定是否来自诊断负担或菜单流程。单批平均不能证明细小提升或退步。

V27核心记录：[v27-core.json](v27-core.json)。旧V27实测为100、72、104、124、85、101、86、95、100、104。

## 界面简化与快捷键更新

前端及批次会话已移除只观察选项。语言标示改为双语，快捷键录入提示不再称为组合键。取消固定F9停止路径：默认停止键仍为F9，更改设置后只使用配置的停止键；原有停止按钮、关闭窗口及失焦检查仍有效。开发者说明按参考界面展示保存内容、目录链接、Issue回报说明及项目链接，不保存视频。任务栏图标使用去掉外侧装饰的蓝框文字版，页首仍保留完整Logo。

269项非界面测试和8项界面测试通过，包含配置快捷键、忽略未配置F9、启动等待及结束期间停止的检查。六种语言的说明框均完成尺寸检查。五个V27识别核心、捕获及游戏画面门仍与冻结源匹配；控制器比较仅额外容许上述固定F9路径移除。25ms起跳时序未改变，未在本轮操作游戏或测量新成绩。
